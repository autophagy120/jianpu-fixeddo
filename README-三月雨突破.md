## 之前一直失败的两个真正原因（都不是算法问题）

### 1. `max_tokens` 给小了 —— 推理模型把预算全花在"思考"上
DeepSeek 的 flash/v4 是**推理模型**：答案前会有几千 token 的思考。
我一直传 `max_tokens=1200`，于是**每次都在思考途中被截断，content 为空**，
看起来像"模型读不出来"。改成 **16000** 后，同一个片段立刻稳定输出。

> 诊断方法：打印 `msg["content"]` 与 `msg["reasoning_content"]` 的长度比。
> 之前是 `content=0 / reasoning=26503`。

### 2. 我自己的 NameError 把结果吞掉了
宽松解析器里写了 `List[List[str]]` 注解，但 `vlm.py` 没 `import List` →
每次调用抛异常，被上层 `except` 吃成空结果。
原始响应其实是对的（`3^ 6^ 1^ 2^ 3^ …`），我误以为"模型不行"。

> 教训：调模型前先打印**原始返回**，不要只看后处理结果。

## 现在有效的方法（已接入）

1. **整行一次读**：整条谱行（全宽）裁出 → 放大 3 倍 → 一次调用。
   比切片可靠得多（切片会引入拼接与上下文丢失），15 行 = 15 次调用。
2. **纵向裁干净**：y 范围取谱行本身 ±6px，避免把下方歌词带进去。
3. **音符串格式**（不带坐标）：模型只输出 `6 1^ 2 3 …`，解析宽松抓最长 token 串。
4. **落位**：单调比例对齐 + 数量不足时**插入**（补漏检），绝不整行平移。
5. **自举传播**：用已确认音符当模板，原生尺寸 1-NN 补同类字形。
6. **红/橙标注**：红=自动确认，橙=待核对，用户只看橙色。
