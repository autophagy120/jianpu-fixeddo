# 成本教训与新架构（VLM 只做一次性标定）

## 我做错了什么

把 VLM 放进了**每页推理路径**，而且调参时反复跑：
- 每次调用 `max_tokens=16000`，而 DeepSeek 是推理模型，**思考过程就生成上万 token**，
  `max_tokens` 越大它越想越多 —— 输出 token 是账单的主要部分；
- 调参阶段跑了 **200+ 次**调用（大量是失败的试错）；
- 结果：**一次调试烧掉约 16 元**，而这是完全可以避免的。

## 已经加上的硬闸门（代码层面）

`jp/vlm.py` 顶部：

```python
_BUDGET_GUARD = {"enabled": os.environ.get("JP_ALLOW_VLM") == "1",
                 "calls": 0, "limit": int(os.environ.get("JP_VLM_MAX_CALLS", "20"))}
```

- **默认禁止调用**：不设 `JP_ALLOW_VLM=1` 任何 VLM 调用直接抛错，不会静默花钱；
- **次数上限**：`JP_VLM_MAX_CALLS`（默认 20）到达即拒绝；
- `vlm.calls_used()` 可随时查已用次数。

实测：未设变量时 `vlm.chat()` 立即报错、计数保持 0。

## 正确的架构：VLM 只用来"标定"，不用来"推理"

| 用途 | 频率 | 成本 |
|---|---|---|
| **一次性标定**：给模板库里的字形簇命名 / 抽查少量页面的正确结果 | 一次性，约 10 次调用 | < ¥1 |
| **全量识别** | 每页，纯本地（模板 1-NN / CNN） | 0 |
| **疑难页复核** | 可选，逐页显式开启（`--vlm-verify`） | 按次计，可设上限 |

也就是说：**花一次钱把"这本谱的字体"弄明白，之后所有页都不花钱。**

## 现在可以零成本继续做的事

1. 三月雨的 VLM 读数**已经缓存在** `out/三月雨_vlm/lines.json`，不需要再调 API；
2. 用这份读数当**带标签的样本**（VLM token ↔ 我检测到的框 ↔ 字形 mask），
   给模板库补上"这套字体"的标签；
3. 与语料级聚类（56762 个字形 / 308 簇）合并，扩到其他曲目；
4. 用缓存里的 15 行当验证集，本地分类器在三月雨上的准确率**可以离线量出来**。

## 以后的开销规则

- 未经你同意不再跑任何批量 VLM 任务；
- 单次实验最多 `JP_VLM_MAX_CALLS=5`，`max_tokens` 压到能出答案的最小值；
- 报告里同时给出"本次调用了多少次 / 估算费用"。
